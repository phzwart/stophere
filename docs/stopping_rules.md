# Phase 4 stopping observers

## Separation from the acquisition trajectory

The formal Phase 4 implementation treats every stopping rule as an observer.
Phase 3 still runs to the hard budget. At each declared check time, Phase 4
records whether a rule would fire and retains its first trigger time. The
observer does not select a point, consume the acquisition policy's random
stream, read future observations, or access the benchmark optimum.

The provisional settings are versioned in
`configs/phase4_stopping_observers.yaml`. They are suitable for implementation
tests but are not frozen for the scientific matrix until the objective scale
and risk interpretation are confirmed with Peter.

## Operational definitions

| ID | Observer | Implemented decision |
| --- | --- | --- |
| S1 | Fixed budget | Fires at the hard budget. This is also the fallback for every other rule. |
| S2 | Incumbent stagnation | Fires when the best observed value has improved by at most the declared gain over the declared observation window. |
| S3 | Negligible expected improvement | Fits the common Phase 3 GP, evaluates LogEI over the complete catalogue, converts the maximum back to objective units, and compares it with the declared EI threshold. |
| S4 | Global confidence gap | Fires when `max_x U(x) - L(x_hat)` is no larger than `epsilon`, where `x_hat` is the returned best evaluated point. |
| S5 | Posterior acceptable regret | Fires when a conservative lower confidence bound for `P(max_x f(x) - f(x_hat) <= epsilon | data)` reaches `1-delta`. |

S3 is a diagnostic EI even when the trajectory was generated by PI, UCB,
Thompson sampling, or MES. Raw acquisition values from those policies are not
treated as interchangeable.

## Probability and numerical error

S4 uses a Gaussian posterior band on the finite catalogue. A Bonferroni
allocation covers both tails, every catalogue point, and every scheduled look.
This is a simultaneous statement conditional on the fitted GP. It is not a
guarantee under kernel, likelihood, hyperparameter, or domain misspecification.

S5 draws joint Matheron posterior paths using BoTorch's random-feature path
sampler. Within each path, the catalogue maximum and recommendation value come
from the same draw. A one-sided Clopper-Pearson lower bound accounts for the
finite number of Monte Carlo paths, and its error allowance is split across
scheduled looks by Bonferroni. The pathwise random-feature approximation is
recorded as a separate numerical limitation.

## Provisional thresholds requiring confirmation

- `epsilon = 0.02` objective units;
- a 10-observation stagnation window with gain threshold `0.002`;
- maximum EI threshold `0.001` objective units;
- S4 total conditional-posterior error `0.05`;
- S5 posterior regret target `0.95` and Monte Carlo family error `0.01`;
- checks after ten post-initial observations, every five evaluations, and at
  the hard budget.

The current benchmark outputs do not all share the same physical scale. The
stoppers therefore cannot silently use normalized regret, because the true
catalogue range is unavailable to a real online stopper. Before the full
matrix, choose either scientifically scaled outputs, per-system tolerances
declared without truth leakage, or a dimensionless tolerance derived only from
observable quantities. Sensitivity analysis may use benchmark truth in the
evaluator, but not inside a stopping rule.

## Validation requirements

Tests verify that adding the observers leaves the selected acquisition points
unchanged, that the hard budget is always checked, and that every rule records
its first trigger. The reduced smoke script covers an easy peak, a hidden
narrow peak, and a Matérn-like random field. It is implementation evidence,
not a performance comparison.
